# The spec

There is no separate specification document, deliberately. The spec is the design pack, kept in one
place so it cannot drift from the decisions it rests on:

| Question                                                | Authoritative document                                              |
| ------------------------------------------------------- | ------------------------------------------------------------------- |
| What idea, and for whom?                                | [01-capture-the-idea.md](../01-capture-the-idea.md)                 |
| Who has what problem, and what does it cost?            | [02-frame-the-problem.md](../02-frame-the-problem.md)               |
| Is the problem real?                                    | [03-validate-before-building.md](../03-validate-before-building.md) |
| What is in v1, with acceptance criteria?                | [04-define-scope.md](../04-define-scope.md)                         |
| What did we measure, and what does the stack look like? | [05-technical-discovery.md](../05-technical-discovery.md)           |
| How is it shaped, and why?                              | [06-design/](../06-design/README.md)                                |
| Why these choices, and what would change them?          | [adr/](../adr/)                                                     |
| What is running, and how do we know?                    | [07-foundation/](../07-foundation/walking-skeleton.md)              |

**If these ever disagree, the ADRs win**, because they are the only documents that record what was
rejected and when to revisit.
